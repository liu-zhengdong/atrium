## 用户在这里要做的事

1. 看现在谁在干什么，有没有卡住或等我拍板的。
2. 看接下来要做什么，每件在等什么（等额度、等本机空出来、等别的任务、等 PR 合入）。
3. 回头看做完了什么：结果（已上线哪一版、失败原因、取消）、PR、用时。
4. 找某一件任务（知道 tN 或记得标题里的词）。

## 涉及的概念和各自的位置

| 概念                                       | 放在哪                                                                                        |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 在做、卡住、等你                           | 在做组「状态」列；卡住的在「谁在处理」列写负责人或秘书，等你的写红字原因                      |
| 审阅中、排队合入、合入中、已合入（等上线） | 在做组，状态用蓝色；「谁在处理」写「合入队列」                                                |
| 排队、就绪、等待中，以及在等谁             | 接下来组「状态」列 +「在等什么」列（上游 tN 可点，PR 号、额度恢复时间写全）                   |
| 上游失败而排不上                           | 接下来组，状态「卡住」橙色                                                                    |
| 紧急                                       | 标题前红色小标；做完了组里不再标                                                              |
| 已上线 vX、已合入、完成、失败、取消        | 做完了组「结果」列；失败原因红字写在「经过」列，取消的标题变淡                                |
| PR、用时、结束时间                         | 「经过」列开头是 PR 号；用时一列；结束日期按天分段（今天 / 昨天 / 09-25），具体时刻在悬停提示 |
| 由谁处理                                   | 在做组「谁在处理」、接下来组「谁来做」、做完了组「谁做的」，同一列位置                        |
| 归属部分、谁派的                           | 标题下一行小字；归属部分只在不是当前这块时写                                                  |
| 专员、执行者                               | 专员胶囊可点到专员页，执行者胶囊可点到执行者页                                                |

状态叫法与状态栏、`top` 一致：在做、卡住、等你、审阅中、排队合入、合入中、已合入、已上线、排队；组标题旁的小计按状态栏头一行的顺序写（等你 · 在做 · 负责人处理 · 秘书处理 · 合入）。

## 为什么这么分

- 范式取 Linear 的分组列表和 GitHub Projects 的分组表：同一页上下三组，各组有自己的表头。三组要回答的问题不同（谁在处理 / 在等什么 / 结果如何），所以第 4、5、6 列按组换内容，但列宽三组共用，任务、专员两列上下对齐。
- 三组在同一页，不做成子页签：用户要「一眼掌握全局」，拆成子页签就得来回点。做完了会越来越多，所以只显示最近 10 件，底部「再看 20 条」，旁边写共多少件。
- 「已合入、等发版上线」放在在做组：状态栏也把它算作合入流水线里的一件，用户说的「做完了」是已经上线。
- 「排队」（已经派了，在等额度或本机空出来）放在接下来组：执行者还没动手。
- 找任务放在页签行右侧，就是原来「进行中 / 全部」筛选的位置；输入后三组同时筛。

## 各页怎么用

- 组织根：新增「任务」页签（放在「组成部分」之后），汇总所有部分；标题下一行写归属部分。
- 部分页：原来的「进行中 / 全部」换成三组，含子部分的任务。
- 专员页：同样三组，不列专员。
- 执行者页：原「交付记录」并进「任务」页签，做完了组就是交付记录（结果、用时、经过都在）；这个执行者没有排着的活时不画接下来组。
- 页签上的数字改成「在做 + 接下来」的件数。

## 考虑过但没选的方案

1. **看板（三列卡片）**：适合拖动改状态，但全景网页只读；卡片放不下 PR、用时、在等什么，做完了那一列会无限变长。
2. **一张表 + 三个筛选胶囊（在做 / 接下来 / 做完了）**：改动最小，但同一时间只能看一组，看不到全局。
3. **一张表按状态排序（现状）**：在跑、排队、已上线、失败、取消混在一起，接下来的排期看不到（见 `before-atrium-light-1440.png`）。

## 需要确认的两点

1. **组名「在做」和状态栏的「在做 N」数目不一样**：网页在做组 8 件（包括等你、卡住、合入），状态栏「在做 3」只数执行者手上的。建议：保留组名「在做」，组旁小计与状态栏对齐；若嫌不一致，组名改成「进行中」。
2. **`top` 表头仍写「在跑」**：实现时建议一并改成「在做」，三处叫法统一。

## 实现要补的数据（另派实现时）

- 节点接口现在只给最近 20 件已结束、10 件待办：做完了需要按结束时间分页（offset/limit）和总数，搜索要走服务端。
- 接下来需要排期字段（就绪 / 等待中 / 卡住、上游与 PR 条件）：复用 `/api/tasks/plan` 的计算，按节点、专员、执行者过滤。
- 在做需要 holder（谁在处理）：复用 `server/tasks/holder.ts`。
- 做完了需要上线版本号、结果原因、「经过」一句话：执行者页的交付记录已经有这些字段，可以复用。
